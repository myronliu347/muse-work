# Todo/Task 两级任务管理 Spec

日期：2026-08-21
状态：待实现
词汇：见根目录 `CONTEXT.md`

## Problem Statement

用户有大量想做的事（写功能、改 bug、整理仓库），散落在对话里、脑子里、POPO 里，没有一个地方能：① 把「想做的事」记下来并排优先级；② 把它细化为可执行的原子任务；③ 让 AI 在隔离环境（worktree）里执行并留痕；④ 执行结果经 AI 复核和人工审核后才算完。现有对话式工作流能做到 ③，但① ② ④ 没有载体——事情开了头就丢了，做完没审核就混进主仓，改坏了难追溯。

## Solution

新增「任务管理」子系统：两级实体 todo（待办，高层目标，带 p0/p1/p2 优先级）→ task（任务，可执行的原子单元）。todo 从会话/手动创建，在专属「规划会话」里多轮对话细化出 task；task 创建时即指定 workdir（git 项目自动开 worktree）并立即入队执行（并发上限 3、FIFO 排队），执行结束自动进「待审核」并触发 todo 的规划会话做一轮 AI 复核；最终由用户人工审核——通过即完成，加评论可继续执行。全部 task 完成或取消后 todo 自动完成。

核心价值：**AI 执行 + 人工审核的闭环**，可追溯、可反复迭代，直到用户验收通过。

## User Stories

1. 作为用户，我想在普通会话里说「记个 todo：xxx」就创建一条 todo，以便顺手记录想法而不打断工作流
2. 作为用户，我想在 todo 列表页手动新建 todo，以便没有对话上下文时也能登记
3. 作为用户，我想给 todo 指定优先级 p0/p1/p2（默认 p1），以便看板按重要性排序
4. 作为用户，我想看到 todo 的来源标记（会话/手动创建/POPO 任务/内部管理平台），以便知道它是从哪来的
5. 作为用户，我想从 todo 打开它的规划会话，以便和 AI 多轮讨论分析这个 todo
6. 作为用户，我想在规划会话里确认任务方案后说「创建 task」，以便只落库我认可的任务
7. 作为用户，我想一个 todo 固定对应一个规划会话，以便讨论历史持续累积、不散落
8. 作为用户，我想给 task 绑定 workdir，以便指定在哪个仓库执行
9. 作为用户，我想在规划会话里让 AI 问我要绑哪个 repo，以便不用跳出对话操作
10. 作为用户，我想 task 创建时即指定 workdir（git 项目自动开 worktree）并立即入队执行，以便创建完不用手动触发
11. 作为用户，我想多个 task 并发执行不超过 3 个、其余 FIFO 排队（排队中仍显示待执行），以便不会把机器打满
12. 作为用户，我想看到 task 的执行过程（执行会话可见、可进会话列表），以便跟踪 AI 在做什么
13. 作为用户，我想 task 每次执行（含继续执行）复用同一个执行会话，以便上下文连续
14. 作为用户，我想 task 执行结束后自动进入待审核并看到执行结果评论，以便知道 AI 做了什么
15. 作为用户，我想即使执行报错/中断，task 也进待审核并注明原因，以便我能决定重试还是放弃，而不是任务无声消失
16. 作为用户，我想 task 进待审核时 todo 的规划会话自动收到进度同步并做一轮 AI 复核，结论评论到任务详情，以便我审核时有多一重视角
17. 作为用户，我想 AI 复核的注入不打断我正在进行的对话（排队等当前回合结束），以便不会被系统消息骚扰
18. 作为用户，我想在 webview 里区分系统注入的消息和用户本人消息，以便知道哪些消息不是我发的
19. 作为用户，我想审核 task 时点「通过」使其变为已完成，以便收口这个任务
20. 作为用户，我想审核 task 时加评论并点「继续执行」使其回到执行中，以便带新要求重新执行
21. 作为用户，我想取消任何未完成的 task（已取消不影响 todo 完成），以便放弃某个任务但不拖垮整个 todo
22. 作为用户，我想 todo 全部 task 完成或取消后自动转为已完成，以便不用手动收口
23. 作为用户，我想取消 todo 时级联取消其所有未完成 task，以便放弃整件事时不用逐个取消
24. 作为用户，我想在任务看板页面查看 todo 列表和 task 卡片（按优先级排序），以便全局掌握进展
25. 作为用户，我想查看每次执行的执行记录（run），以便追溯任务执行历史
26. 作为用户，我想 todo/task 数据持久化到磁盘（重启不丢），以便长期追踪
27. 作为用户，我想用 markdown 写 todo 和 task 的描述（加粗、列表、代码块等），以便记录结构化信息
28. 作为用户，我想已取消的 todo/task 不显示在看板主视图（仅归档保留），以便看板只呈现有效事项
29. 作为用户，我想规划会话在首次点击「打开规划会话」时才创建，以便不建一堆空会话
30. 作为用户，我想非 git 项目的 workdir 直接执行（不建 worktree），以便在普通目录也能跑任务
31. 作为用户，我想在待执行状态下手动编辑 todo（标题/描述/优先级）和 task（标题/描述），以便创建后纠正内容；执行中/待审核锁定、归档不可改
32. 作为用户，我想 task 进待审核时收到通知（应用未聚焦弹系统通知、聚焦时看板 badge 计数），以便及时去审核

## Implementation Decisions

### 实体与存储

- 新增三个实体：Todo、Task、Comment（+执行记录 Run），字段见 `CONTEXT.md` 与设计确认。todo 带 `priority`（p0/p1/p2，默认 p1），task 无优先级。todo 与 task 的 `description` 均为 markdown 格式，UI 按 markdown 渲染
- 存储沿用分文件模式：todo 索引单文件 + 每 todo 一个目录（tasks/comments/runs 各一文件）；内存 Map + JSON 原子写，沿用既有 sessionStore 模式。**不使用 SQLite**（无现有依赖、避免 Electron 原生模块 ABI 问题）
- 数据目录 `~/.muse-work/db/`（与现有 sessions.json 等并列）

### Server 层

- 新增 REST 路由组：todo/task 的 CRUD、状态迁移（创建第一个 task→todo 进行中；全部完成或取消→todo 已完成；取消 todo 级联取消子 task）、评论、执行记录、规划会话/执行会话的创建与关联、workdir 绑定
- **手动编辑**：todo 可改标题/描述/优先级（来源不可改）；task 可改标题/描述（workdir 不可改）。仅「待执行」状态可编辑；执行中/待审核锁定，已完成/已取消归档不可改
- 会话关联：todo 存 `planningSessionId`（每 todo 固定一个，**用户首次点「打开规划会话」时懒创建**）；task 存 `executionSessionId`（每 task 固定一个，复用）。规划会话由 todo 详情入口创建/打开；执行会话由 task 执行时创建
- 执行会话创建用 `permissionMode: "bypassPermissions"`（避免权限请求挂起无人应答）
- **执行调度**：task 创建时即需指定 workdir（在规划会话里由 AI 询问用户确认；git 项目自动开 worktree，**非 git 项目直接在该目录执行**），创建即入队执行；**全局**并发上限 **3**（所有 todo 的 task 共享槽位），超出部分 **FIFO 排队**（排队中仍显示「待执行」，不新增状态）。**调度器为常驻循环**：server 启动即挂定时器定期扫队列，把可执行的 task 推进空闲槽位；重启后 queued 的 task 自动恢复调度（槽位空即自动开跑，无需用户手动触发）。执行完成释放槽位后调度下一个排队 task
- 状态迁移以事件驱动：task 执行结束（含报错/中断，runTurn 结束时判定）→ task 转待审核 + 写 result 评论 → **触发注入**（向 planningSession 的会话注入进度消息 + 触发 AI 复核轮）+ 复核结论写 note 评论
- **通知**：只通知「task 进待审核」一个事件（唯一需要用户行动的事件）。两种形式：① **应用内右上角通知组件**（业界常规形态，类似 Radix Toast——图标 + 标题「Muse · 任务待审核」+ 正文 `todo 标题 · task 标题 待审核` + meta（时间/优先级/AI 复核状态）+ 关闭按钮，滑入动画，8s 自动消失，多条堆叠，点击跳转对应 task 详情抽屉）；② 看板入口 badge（未审核 task 计数，聚焦时显示）。复用/扩展现有 webview ToastStack 通道
- 注入链路：复用现成消息入口，agent 空闲时自动重建并恢复历史（已验证）。**需新建**：sendMessage 增加来源标记字段，区分「系统注入」与「用户本人」；广播与消息落盘带上该标记
- worktree 创建：server 侧无此能力（在 desktop 主进程），需接通 IPC 或新增 server 接口调用

### Webview 层

**任务看板主视图（左右布局，原型已定稿：`docs/superpowers/prototypes/2026-08-21-todo-task-board-prototype.html`，仅 A 变体胜出）**：

- 左侧 todo 列表：顶部「+ 新建 TODO」入口（手动创建）；按优先级排序（p0→p1→p2），每行 = 优先级徽标 + 标题（行内右侧：打开规划会话 chat 图标 + 取消 ✕ 图标）+ 第二行状态徽标 + 来源；点击选中 todo
- 右侧任务看板：选中 todo 的 task 按状态分 4 列（待执行/执行中/待审核/已完成），卡片 = 标题 + 描述摘要 + worktree + 底部「打开执行会话」图标；点击卡片 → 右侧详情抽屉；**待执行 todo（无 task）→ 不显示看板列，居中提示「打开规划会话」引导**
- task 详情抽屉：标题 + 状态 + md 描述 + 执行环境（workdir/worktree）+ 操作按钮行 + 执行记录 + 审核讨论（评论流 + 输入框）
- **编辑**：todo/task 详情抽屉有「编辑」按钮（铅笔图标）→ 切换为表单（todo：标题/描述/优先级；task：标题/描述）→ 保存更新。仅待执行状态显示编辑按钮
- 操作按钮全部图标化（codicon + Tooltip）：通过/继续执行/开始执行/打开执行会话/取消/绑定 workdir；打开方式 = 在编辑器打开、在终端打开（对 workdir）；「操作」字样标题不显示；已完成/已取消任务无状态操作按钮。**待执行 task 的操作为「开始执行」（触发入队）**——「绑定 workdir」不单独存在（创建时已确认 workdir）
- 看板卡片/列表行**只保留「打开执行会话」**，具体操作（通过/继续执行/取消/绑定）只在详情抽屉内
- 评论输入框常驻审核讨论区（textarea + 发送，支持 markdown，⌘/Ctrl+Enter 发送）
- todo 与 task 描述按 markdown 渲染（复用现有 md 渲染能力，如消息正文的渲染管线）
- 「已完成」「已取消」的 todo 均不显示在看板主视图（数据保留，仅归档）；task 的「已取消」不显示、「已完成」保留在列内
- 消息渲染：区分系统注入消息（来源标记）与用户消息，系统消息用独立样式
- 侧边栏新增入口，MainView 枚举扩展

### AI 能力（会话入口）

- 内置插件 skill + 脚本调 HTTP API：会话说「记个 todo」→ AI 执行脚本创建。形态参考既有插件（superpowers/mattpocock）
- 规划会话提示词：指导 AI 引导用户把 todo 细化成可执行 task，只有用户明确说「创建 task」才落库

## Testing Decisions

原则：只测外部行为（HTTP 响应、状态迁移结果、注入是否发生、UI 渲染），不测实现细节。状态机与触发链是核心，必须覆盖。

- **Seam 1 — Server REST API + 状态机**（最高 seam）：todo/task CRUD、状态迁移全路径（创建 task→todo 进行中；全部收口→已完成；级联取消；task 取消不影响 todo 完成）、评论/执行记录、workdir 绑定。先例：`tests/popoRoutes.test.ts`、`tests/sessions.control.routes.test.ts`（Hono app + 内存 store 直测）
- **Seam 2 — Server 注入链路**：task 进待审核 → 自动向规划会话注入（断言注入消息带来源标记、agent 空闲时重建后仍注入、复核结论评论落盘）。先例：`sessionRunner.lifecycle.test.ts`
- **Seam 3 — Webview 看板组件**：todo 列表/详情、task 卡片状态渲染与操作（通过/继续执行/取消/绑定 workdir）、系统消息与用户消息区分。先例：`packages/webview/tests/components/`、`apiClient.test.ts`
- **Seam 4 — E2E 完整链路**（必需）：「会话记 todo → 打开规划会话创建 task（指定 workdir）→ 入队执行 → 待审核 + AI 复核 → 用户通过 → todo 已完成」。先例：`packages/webview/e2e/demo/`
- **Seam 5 — 执行调度**（常驻调度器 + 全局并发 3 + FIFO 队列）：创建第 4 个 task 时排队不执行、执行完成释放槽位后按序启动、排队中状态仍为待执行、重启后 queued 自动恢复调度。先例：`sessionRunner.lifecycle.test.ts`

## 边界场景

- **执行中退出应用**：task 回「待执行」（run 中断，不自动重跑，用户可重新触发「开始执行」）；排队中的 task 不丢失，重启后由常驻调度器按原顺序自动恢复调度（run 的 queued 状态落盘持久化）
- **server 崩溃/重启**：执行中的 task 回「待执行」（run 标记 interrupted）；排队中的 task 继续排队，调度器启动后自动恢复
- **执行中取消**：中止执行会话、task 转「已取消」、run 标 canceled；worktree 立即删除（执行中强删有风险，但用户已拍板立即删）
- **task 成功后清理**：用户审核通过（已完成）→ 自动删除 worktree 与执行会话（复用 desktop 删除会话链路），执行会话不再存在；执行中断/取消/继续执行时 worktree 保留
- **继续执行循环**：不限制次数；每次执行有 run 记录 + 评论留痕，循环由用户驱动
- **AI 复核注入失败**：重试一次，仍失败则跳过——task 不阻塞在待审核（人工审核是必经之路），评论标注「AI 复核失败」
- **非 git workdir**：不建 worktree，直接在该目录执行；成功后无 worktree 可删，仅清理执行会话

## Out of Scope

- POPO 任务 / 内部管理平台来源的自动同步（本期仅来源标记，创建入口为手动/会话）
- task 级优先级（仅 todo 有，仅排序，不参与执行调度——调度为 FIFO）
- 调度优先级策略（本期 FIFO；若未来需要按 todo 优先级调度，属增强）
- 规划会话的 AI 复核结论自动放行（AI 复核仅参考，人工审核是唯一放行途径）
- 看板拖拽/看板列自定义等高级 UI
- 已完成 todo 的归档视图（本期已完成/已取消均不显示，无专门归档入口）

## Further Notes

- 领域词汇以 `CONTEXT.md` 为准（todo/task/规划会话/执行会话/AI 复核/人工审核/绑定 workdir）
- 关键技术前提已探查验证：消息注入 + agent 自动重建链路现成；需新建的是来源标记（server 三处：sendMessage/广播/消息模型 + webview 渲染）
- 本 worktree 代码状态较旧（无 mattpocock 插件、无既有 db 目录），实现前需确认工作区同步状态
- todo 优先级仅排序展示，无调度语义；执行调度为并发 3 + FIFO（用户已拍板）
