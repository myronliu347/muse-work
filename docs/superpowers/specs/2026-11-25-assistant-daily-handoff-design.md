# 助手每日收工交接 — 设计说明

日期：2026-11-25
状态：v1 已实现
范围：助手（`origin=assistant`）的每日交接与换上下文；设置页开关与手动收工

## 1. 问题

助手只有一条长期会话。长期不清、反复压缩之后，摘要会一层层丢掉「为什么」，旧结论也容易和新状态打架，表现为降智。
人换班时会写一张交接单；助手也应该在一天结束时把当前状态写下来，第二天用一个干净上下文接着做，而不是继续背摘要。

## 2. 目标与非目标

**目标**

- 每天到点（默认 04:00）自动收工：助手自己写交接 → 清空助手模型上下文 → 把交接注入新上下文。用户可见的聊天记录保留，界面上无感。
- 开关默认开启，可以关；关掉后不自动跑，手动收工仍可用。
- 手动「立即收工」入口：设置页按钮 + 助手聊天里的 `/收工`（`/handoff`）。
- 只在助手空闲时执行；有事件在排队、正在跑、正在压缩，都不动。
- 交接必须由助手自己写；写不出来（报错、空响应、超时）就不换上下文，保留原状态等下一次/手动重试。
- 不删 `db/assistant-messages`、不广播 `assistant:cleared`、不往聊天里写“已收工”通知；换班对用户不可见。
- 交接写得短、可读、下一个助手能直接接上。

**非目标**

- 不换各 Issue 的工作会话；只换协调者（助手）。
- 不并发开多条助手会话。
- 不启用新的 handoff writer 子会话；v1 用助手的 `askBtw` 单轮 fork 写，复用助手自己的上下文/模型，但没有工具、不产生可见回合。
- 不做跨天聊天记录的 UI 浏览；聊天记录保留在原处，不另做归档/回放。

## 3. 行为

### 3.1 定时

- 配置：`db/assistant-handoff.json`，缺省 `{ enabled: true, hour: 4 }`。
- 调度器每 30 秒检查一次；本地时间到 `hour` 且当天还没尝试过，才进入候选。
- 以下情况跳过当天，并记 `lastAttemptAt`：
  - 助手会话不存在；
  - 当天助手已经有活动（`session.lastActiveAt > 当天 hour`）；
  - 超过 `hour + 12h` 才打开应用；
  - 没有任何新进展、消息或 Issue 变化（`no_activity`）。
- 助手忙（运行时 working、队列非空、session running、compacting）时不标记尝试，下一拍再试；超过窗口则放弃当天。

### 3.2 手动

`POST /assistant/handoff/run`：

- 忙则 409，不产生任何写入。
- 空闲则立即执行；即使开关关闭也允许。
- 成功后返回交接全文和路径。

### 3.3 收工顺序

1. 从 `IssueStore.listActive()` + `issueProgress` + 最近消息收集事实，拼成素材。
2. 调 `runner.askBtw`，把素材交给助手，让助手直接写交接正文（180s 超时；不能调用工具、不能发消息）。
3. 校验/清理模型输出；失败则中止，不写文件、不清空上下文。
4. 写 `<assistantWorkdir>/HANDOFF.md`（覆盖）。
5. 追加 `<assistantWorkdir>/JOURNAL/YYYY-MM-DD.md`。
6. `runner.clear(assistantId)`；失败则中止，不动聊天记录。
7. `runner.appendSystemNote(assistantId, 带“【收工交接】+ 文件路径”前缀的交接全文)`，作为新上下文的系统注记；新会话不需要主动读文件，压缩后可以按路径 `Read`。
8. 广播 `assistant:handoff`（内部事件，界面不显示通知）。
9. 写配置的 `lastRunAt` / `lastAttemptAt`；清 `lastError`。

### 3.4 交接内容

```markdown
# 交接 · 2026-11-25 04:00

给下一个自己：这是收工时的状态。细节在 Issue 台账和 `JOURNAL/2026-11-25.md`。

## 现在在跟（N）
- **p0 · 标题**（`issueId`）· 状态 · 清单 3/5
  - 最新：…
  - 下一步：…

## 今天有动静
- 22:14 标题：…

## 等你拍板
- 标题：待审核 / 待关闭 / 等你回话

## 明天先做
1. …

## 最近对话
- 他：…
- 我：…
```

约束：

- 素材最多 12 个事项、10 条进展、4 句对话；单行 180 字；交给模型前裁剪。
- 助手输出限制 16K 字符；空响应、报错、超时都视为失败，不换上下文。
- 不写完整 Issue 描述、不写密钥、不复制工具输出。
- 交接全文会作为系统注记直接进入新上下文；文件路径也写在注记里，助手需要回看原文时用 `Read`，不依赖它自己想起来去读。

## 4. 接口与设置

- `GET /assistant/handoff` → 开关、时间、下次/上次、当前交接、路径。
- `PUT /assistant/handoff` → `{ enabled?, hour? }`；hour 0–23 整数。
- `POST /assistant/handoff/run` → 手动收工。

设置页把原「助手」和「记忆」合并成一个「助手」tab，内部左右布局：

- 左侧目录：每日收工 / 记忆整理 / 知识库；目录贴左，宽度/背景/选中样式对齐会话列表侧边栏（232px、`surface-session-list`、右侧分隔线），右侧内容区 880px 居中。
- 「每日收工」：开关（默认开）、收工时间 Select（00:00–23:00，默认 04:00）、下次/上次/当前状态、「立即收工」按钮、当前交接预览与路径。
- 「记忆整理」：原 MemoryDreamSettings。
- 「知识库」：原 AssistantLearningLibrary，从记忆页底部挪出来，直接以双栏面板展示（左列表、右预览，各自滚动），不再用「查看知识库」弹窗；知识库这一栏铺满助手页剩余空间（侧边栏保留），不再限 880px。

助手聊天输入 `/收工` 或 `/handoff` 等价于手动收工；忙时不执行，提示稍后。

## 5. 测试

- 配置默认开启、持久化、hour 校验。
- 素材包含在跟事项、进展、下一步；模型输出经过裁剪/校验。
- 手动收工：助手写 HANDOFF、写 JOURNAL、清空内部上下文、注入、广播、配置更新；聊天记录不变。
- 忙时不动；定时无新活动跳过；助手写不出来不换。
- 路由读写与 409。
- 调度器：到点空闲执行；关闭/未到点不执行；当天已活动则跳过。
- 设置组件：开关默认开、关闭调用、手动收工确认。
