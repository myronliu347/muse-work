# 桌面布局 — 设计说明

日期：2026-10-22  
状态：原型已确认，待实现  
范围：桌面端 webview 的导航、Muse Bot 主页、Issue 会话与右侧面板。不改助理事件循环，不改 Issue 的服务端模型。

视觉以原型 `layout-v8` 为准。本文只记已经确认的行为。

## 问题

现在的桌面侧栏把新对话、自动化、Muse Bot、普通会话和待办 Issue 放在同一列。Issue 会话从待办点进去，会进入会话详情。右侧文件、终端、浏览器、变更和待办抢同一块区域。

## 目标

- 左侧只有一条图标栏：Muse Bot、会话、自动化、设置。默认落在 Muse Bot。
- 会话列表只放普通会话。Issue 不出现在这里。
- Muse Bot 与已打开的 Issue 会话用中间标签切换。
- 待处理和待办是列表。点一项只改变右侧面板，不打开中间会话。
- 右侧面板保持文件、终端、浏览器、变更，并增加「详情」标签。
- 窗口够宽时，待处理和待办以卡片放在对话右上角；不够宽时收成两个图标。

## 非目标

- 不改助理队列、消息存储和工具。
- 不把 Issue 会话并进「会话」列表，也不从会话树打开它。
- 不用返回按钮离开 Issue 会话。
- 不把待办做成常驻遮罩盖住消息。
- 不改文件、终端、浏览器、变更各自的内容能力，只改它们所跟随的 Issue，以及标签栏多一个「详情」。

## 左侧图标栏

宽度 52px。每项只显示图标，悬停出名称。顺序固定：

| 顺序 | 名称 | 图标 | 进入 |
| --- | --- | --- | --- |
| 1 | Muse Bot | 星芒（AI 助手）：大星加右上、左下两处小十字。线宽 1.6 | 中间的 Muse Bot 区域。有 Issue 标签打开时，这一项仍保持选中 |
| 2 | 会话 | 对话气泡 | 普通会话列表 |
| 3 | 自动化 | 时钟 | 现有自动化页 |
| 4 | 设置 | 六齿齿轮，中心圆孔。线宽 1.6 | 设置页 |

设置页占中间整页，使用现在设置对话框里的内容，不再以对话框打开。自动化页同样占中间整页。这两页不显示右侧面板。

## Muse Bot

应用打开后的主页。中间顶部是标签栏。

- 第一个标签永远是「Muse Bot」，不能关闭。
- 没有消息时，中间是空状态：muse 标志和「今天想让我帮你做些什么？」。
- 有消息时显示助理对话。输入框沿用现在的发送、工作目录和模型行。
- 从「会话」「自动化」「设置」再点回 Muse Bot，回到离开前的那个标签，不重置已打开的 Issue 标签。

Issue 标签只在用户从右侧详情里打开会话后出现。标签文字是 Issue 标题，过长省略。标签上的关闭只关掉这个标签；关掉的是当前标签时，回到 Muse Bot。已打开的 Issue 标签只在本次运行内保留，重启不恢复。

标签切换只改中间的对话，不改右侧当前选中的待处理或待办。

## 待处理与待办

两份列表，数据仍是现在的助理队列和 Issue 列表。

- 待处理：队列项，带类型（聊天、自动化等）和标题。
- 待办：Issue 标题和优先级。

点列表中的一项：

- 选中这一项。
- 右侧面板切到「详情」，内容换成这一项。
- 中间标签保持不动。不创建 Issue 会话，也不滚动到会话列表。

视口宽度至少 1240px 时，两张卡片放在中间对话的右侧、顶部对齐，各自独立圆角和阴影，不伸到底，也不盖住消息。对话列因此变窄，消息在卡片左边。

视口窄于 1240px 时，卡片不出现。标签栏右侧是两个图标按钮，角标分别是待处理和待办的数量，悬停显示「待处理」「待办」。点图标打开对应列表，再点一项的效果与点卡片相同，并收起弹出层。

## 右侧面板

标签顺序：详情、文件、终端、浏览器、变更。

「详情」是一块独立内容，不再铺在另外四个标签上面。

选中的是 Issue 时，详情显示：

- 标题
- 状态和优先级，例如「执行中 · P1」
- 清单
- 中间当前标签还不是这条 Issue 时，显示按钮。会话还没打开时按钮为「打开会话」；已经打开但不在当前标签时为「切到会话」。当前正在看这条会话时不显示按钮。

「打开会话」在中间加上该 Issue 的标签并切过去。「切到会话」只切标签。两条都不改变右侧正在看的标签。

选中的是待处理时，详情显示类型、标题和这条事件的正文，没有「打开会话」。文件、终端、浏览器、变更继续显示最近一次选中的 Issue。还没有任何 Issue 时，这四项保持现在不按 Issue 过滤的工作区。

选中的是 Issue 时，文件、终端、浏览器、变更的内容跟着这条 Issue。点列表切到详情之后，用户仍可手动点到文件等标签；下一次点列表会再回到详情。

进入主页时，若已有待办，详情显示第一项，中间仍是 Muse Bot。没有待办、也没有待处理时，详情为空，中间仍是 Muse Bot 的空状态。

## 会话

「会话」里只有置顶和普通工作区会话，结构沿用现在的会话树，去掉待办 Issue 分组。

点一条普通会话，中间是这条会话的对话，右侧仍是当前选中项的面板。这里不出现待办卡片，也不出现 Muse Bot 的标签栏。

## 与现有代码的边界

实现时改 webview 的桌面壳，不改服务端协议。

- `DesktopShell` 的默认页改为 Muse Bot，而不是当前会话。
- `DesktopSidebar` 收成上述四个图标。`SessionTree` 不再渲染 Issue 分组。
- `ChatApp` 在当前会话 id 变化时把视图设回 chat 的逻辑，不能把用户从 Muse Bot 或 Issue 标签拽走。
- Issue 会话作为 Muse Bot 区域内的标签打开，不调用会跳进「会话」的选择会话路径。
- `panelTabs` 与 `DesktopPanelDock` 增加「详情」。文件、终端、浏览器、变更的种类和标签名保持不变。
- 设置入口从对话框改为上述设置页。
- 跟随调整的测试包括：侧栏会话与 Issue 分组、Muse Bot 选中态、自动化入口、设置与登录入口、桌面首屏同时断言会话项和 Issue 区的用例。

## 自查

- 列表点击、打开会话、标签切换、右侧标签，四件事各自只改自己那一块。
- 窄窗口与宽窗口是同一套列表，只是卡片和图标两种呈现。
- Issue 不进入会话列表，会话列表也不提供打开 Issue 会话的入口。
